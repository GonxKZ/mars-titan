## Qué se quiere investigar

Los mercados cambian, las noticias llegan a distintas horas y una parte de la información financiera se publica después del periodo al que se refiere. En estas condiciones, una buena predicción sobre un histórico no basta para demostrar que un modelo generaliza.

MARS-TITAN estudia si la memoria neuronal y la selección de episodios aportan información para predecir retornos residuales. Utiliza precios, noticias, fundamentales y gráficos de **FinMultiTime**, junto con contexto macroeconómico. La edición histórica desde 2000 conserva todos los datos utilizables y sus ausencias explícitas. La comparación estricta mantiene por separado las filas con cuatro modalidades y los 140 indicadores observados. Cada comparación utiliza las mismas filas y cortes para todos sus modelos.

La [dirección arquitectónica](docs/research/titans-mac-architecture.md) conserva el candidato GRU con banco episódico, añade una referencia Transformer compacta y adopta Titans-MAC como núcleo identificable para otra adaptación. MARS-TITAN incorpora sus modificaciones sobre ese núcleo mediante componentes desactivables, comprobados sin aprendizaje. La memoria neuronal de Titans guarda asociaciones en pesos rápidos y usa pérdida asociativa, gradientes, momentum y olvido. Su memoria persistente aprendida y el banco episódico del proyecto son estados diferentes. CM-v1 continúa como variante independiente, desactivada por defecto.

La investigación incorpora mecanismos de aprendizaje y memoria, recurrencia interna de pocos pasos y contexto macroeconómico. La inspiración biológica se traduce en hipótesis sobre retención, adaptación y reaprendizaje. Los antecedentes recientes, incluidos DeepSeek y modelos financieros con memoria, sirven para decidir qué comparar y qué técnicas pueden ser útiles en una GPU pequeña.

La pregunta principal es: **¿mejora una memoria adaptativa de eventos la predicción de retornos residuales fuera de muestra, con un presupuesto de cómputo comparable y después de controlar la fuga temporal?** La utilidad financiera se examinará mediante simulaciones con costes. Una mejora predictiva no implica por sí sola rentabilidad.

## Campaña sobre la edición desde 2000

Estado revisado el 18 de octubre de 2026. La campaña reentrenará desde cero todos los modelos con las mismas filas de la edición histórica con máscaras (`historical_masked_2000_v1`). La edición v3.1 y sus objetivos residuales están generados y verificados. Se ha ejecutado un [microensayo de 28 ajustes](reports/research/memory-microstudy-20261018/README.md) con cuatro activos, una época y evaluación en 2005. Ninguna configuración supera el MAE del residual cero. C+M reduce el error frente a su B, pero la comparación completa sigue pendiente. La protección global del aprendizaje permanece activa y la campaña no se ha lanzado. El [plan de la campaña](docs/research/training-campaign-2000.md) describe cada etapa y el [protocolo walk-forward v2](docs/research/walk-forward-2000.md) fija sus ventanas.

El [estudio combinado de memoria](docs/experiments/combined-memory-v1.md) está preparado con 83 trabajos, cohortes de 64 y 16 instrumentos y dos épocas. La [verificación de composición](reports/engineering/combined-memory-20261018/README.md) comprueba lectores sobre PT1, PT5, PT6 y contexto PT4, con cobertura, CRAP y 14 mutantes detectados. Las ejecuciones de esta ampliación están pendientes.

La [verificación técnica del 17 de octubre](reports/engineering/validation-20261017/README.md) concilia 12.010 casos de pytest, con 11.398 superados y 612 inicialmente omitidos. El [seguimiento del 18 de octubre](reports/engineering/omitted-tests-20261018/README.md) resuelve esas 612 omisiones con fixtures, incluidos 147 casos CUDA, y añade 28 pruebas y 136 regresiones superadas. Corrige el gancho de AdamW anclado y comprueba los pasos nativos de optimizador con sanitizadores. El [diagnóstico de reservas CUDA](reports/engineering/cuda-lifetimes-20261018/README.md) atribuye las asignaciones al cierre y registra 300 ciclos sin crecimiento observado. Conserva el código 99 de memcheck y el fallo de inicialización de CUDA con ASan/UBSan. Las pruebas y el contraejemplo formal de memoria no acreditan una mejora predictiva.

La [edición v3.1](docs/data/edition-v3-1.md#ejecución-del-10-y-11-de-octubre) sustituye a la v3. Lee el texto numérico de los precios con redondeo correcto, admite las filas cuyo único defecto es un desorden OHLC por redondeo de la fuente, conserva con máscara las ventanas con sesiones ausentes en todo el mercado y calcula todos sus vectores en FP32 estricto. Recorre los 5.676 candidatos y codifica 5.023 activos (4.213 de EE. UU. y 810 de China), 15 de ellos sin muestras. Reúne 18.698.976 muestras de 64 sesiones, 1.622.952 más que la v3 y sin perder ninguna sesión. Cada fila conserva las posiciones de precios, noticias, gráficos, fundamentales y 140 indicadores macro con nivel, presencia y antigüedad, además de cinco bits de presencia por modalidad. Precios, gráficos y macro están presentes en todas las filas. Los fundamentales aparecen en el 32,5 % (38,1 % en EE. UU. y 0,7 % en China) y las noticias en el 16,9 % (17,5 % y 13,1 %). La verificación del 11 de octubre comparó cada activo con la v3 antes de sustituirlo, contrastó 74.748 textos heredados sin ninguna diferencia y recalculó en la GPU una muestra de 512 gráficos y 256 textos, idénticos bit a bit ([recibo](reports/data/edition-v3-1-verification-20261011.json)).

Los objetivos residuales (`targets-v3.1`) dejan 17.142.187 filas de entrenamiento hasta 2022 (14.565.147 de EE. UU. y 2.577.040 de China) y 1.235.785 de validación en 2023 (1.040.641 y 195.144), de 5.008 activos. Se excluyen 321.004 filas con su motivo: 309.838 sin historia suficiente para el residual, 1.182 sin la sesión siguiente, 4.995 con el objetivo posterior al corte y 4.989 purgadas porque su objetivo cruza la frontera entre particiones. Las filas aceptadas y las excluidas suman exactamente las muestras de la edición. Una verificación independiente recalculó 223.459 etiquetas de 60 activos con la referencia en pandas, distinta del motor NumPy que las generó, y no encontró ninguna diferencia. El año 2024 sigue sellado. La edición v3 y sus objetivos, verificados el 9 de octubre ([recibo](reports/data/historical-edition-v3-targets-20261009.json)), quedan como historia.

El [diagnóstico de la etiqueta residual](reports/targets/diagnostics.md) se hizo sobre la v3 y se [repitió sobre la v3.1](reports/targets/diagnostics.md#repetición-sobre-la-v31) con el mismo código y la misma declaración. Se conserva la ventana de 252 sesiones y no se recortan extremos. De los 20 mayores residuales de EE. UU., 19 son de valores que abren por debajo de 1 USD o negocian menos de 1.000 acciones en la sesión.

La campaña elegida es A v2, con un modelo conjunto US+CN y reentrenamiento anual desde cero. El [protocolo conjunto v3](docs/research/walk-forward-2000.md#protocolo-conjunto-v3-de-la-campaña-a-v2) conserva todo el pasado admisible desde 2000, valida antes de calibrar y evalúa el año siguiente completo. El diseño inicial de A por mercados separados y la variante B de reentrenamiento cada 36 meses se conservan como antecedentes y no son la receta elegida.

El 9 de octubre, antes de cualquier resultado, el diseño cambió a la [campaña A v2](docs/research/training-campaign-2000.md#campaña-a-v2-con-modelo-conjunto), que es la que se lanzará. Todas las familias entrenan un único modelo conjunto US+CN con el [protocolo conjunto v3](docs/research/walk-forward-2000.md#protocolo-conjunto-v3-de-la-campaña-a-v2), que empieza como el de EE. UU., con la primera validación en abril de 2004 y 19 ventanas. China entra en el ajuste en cuanto tiene filas y sus métricas cuentan desde 2011. `transformer_compact`, `titans_mac_online` y `mars_titan_m1` se entrenan además por separado en cada mercado como controles del efecto de agrupar. Los casos de búsqueda usan la semilla 42 y el caso elegido en validación se repite con 43 y 44. Las etapas siguen un [walk-forward por etapas](docs/research/walk-forward-2000.md#walk-forward-por-etapas-de-la-campaña-a-v2): el postentrenamiento parte de la base de la ventana anterior y solo ajusta con filas que no vio, y la RL ajusta con las tres evaluaciones anteriores a su validación.

La [configuración de A v2](configs/baselines/historical-masked-campaign-a-v2.json) declara 3.177 ajustes de la campaña base, con las referencias neuronales, Ridge, XGBoost, los cuatro controles de Titans-MAC y las dos extensiones PT1 de `titans_mac_online`, la GRU candidata, MARS-TITAN con M0 a M3, K = 2 y 4, K = 4 con episodios de la primera lectura y los ocho modelos B6 (dos con la regla kalman de PT3), y CM-v1, más 133 trabajos del control en línea `transformer_compact_online`. La [etapa de adaptadores de A v2](configs/posttraining/historical-masked-adapter-stage-a-v2.json) prevé 8.694 ajustes con la matriz v3 en las 18 ventanas con padre (270 de ellos de la [continuación anclada](docs/engineering/adapter-variety.md#asimetría-del-decaimiento-y-continuación-anclada) y 1.620 de los [objetivos lineales de #128](docs/engineering/masked-posttraining.md#objetivos-de-la-corrección-lineal-de-128), que se comparan pero no entran en la cadena), 1.710 predicciones del padre congelado y 1.805 selecciones de la cadena. La [etapa de políticas](docs/research/training-campaign-2000.md#etapa-de-políticas-por-ventana) tiene dos niveles. El primero aplica KLPO terminal y las cinco referencias sin aprendizaje (efectivo, compra inicial, regla del 50 %, cartera 1/N e índice de mercado) a los 33 predictores con cadena. El segundo compara las tres variantes PPO, Double DQN, GRPO, Dr. GRPO y GSPO sobre `transformer_compact` y `titans_mac_online`. En A v2 suman 3.384 ajustes y 3.663 ejecuciones de referencia. La declaración original de A, con modelos separados por mercado, conserva sus recuentos (2.385 ajustes en su configuración y 5.985 con la [declaración ampliada](docs/research/training-campaign-2000.md#declaración-preparada-de-las-familias-pendientes), 10.962 de adaptadores y los mismos 3.096 ajustes de políticas) y sus pruebas, pero no es la elegida. Son recuentos de plan fijados por pruebas.

Antes del lanzamiento hay que revisar el estado técnico, completar las mediciones pendientes y autorizar expresamente el aprendizaje. La regeneración bit a bit con modelos ajustados aún no se ha podido comprobar. Con los recuentos reales de las vistas, la retención v2 no cabía por las tablas de los adaptadores (953,3 GB de pico). La retención v3 conserva la etapa entera, guarda sus agregados y libera sus tablas por bloques tras regenerarlas idénticas, con 54,7 GB conservados y 92,6 GB de pico frente a 131 GB libres ([estimación](reports/engineering/campaign-storage-a-v2-v31-v3-20261014/README.md)). La campaña A v2 fija las opciones de memoria medidas en `cuda:0` (`accumulation_rows` 1.024 en Titans-MAC y en los núcleos de CM-v1 y 128 sin `recompute` en la GRU candidata) y cita su [recibo](reports/engineering/campaign-kernels-20261009/README.md#opciones-recomendadas-en-las-recetas). Una [prueba de extremo a extremo](reports/engineering/campaign-kernels-wiring-20261010/README.md#recorrido-hasta-el-entrenador) comprueba que esas opciones, la precisión y el lote llegan a cada entrenador. La medida usó la edición v3 y se repetirá sobre la v3.1. Con la variante A ya elegida, la [orden de caudal](docs/research/training-campaign-2000.md#medición-de-caudal) no decide nada. La duración real se medirá con los primeros trabajos. Según la estimación del medidor con la receta de campaña, un tramo de `mac_online` con 5.023 flujos necesitaría 14,74 GiB sin acumulación y 1,24 GiB con `accumulation_rows=128`, y ninguna variante de Titans-MAC cabría en los 8 GiB de la GPU sin acumular. En la GRU candidata con 512 activos, el pico neto medido pasa de 1.157,8 MiB sin acumulación a 256,6 MiB con `accumulation_rows=128`. Los núcleos de CM-v1 comparten la receta de Titans-MAC porque la penalización C [acumula por bloques de flujos](docs/experiments/mars_titan_cm_v1/factorial.md#acumulación-por-bloques-con-c) con el mismo gradiente que el tramo completo. Las medidas de rendimiento están en el [informe de núcleos](reports/engineering/campaign-kernels-20261009/README.md) y en el de [opciones, medoids y perfiles](reports/engineering/campaign-kernels-wiring-20261010/README.md), y la proyección de disco en el [recibo de almacenamiento](reports/engineering/campaign-storage-20261009/README.md). La estimación vigente de disco ya usa A v2 y los recuentos de las vistas v3.1. Sigue condicionada a que cada tabla se regenere idéntica antes de liberarla. Los recibos de las ediciones y las estimaciones anteriores conservan su fecha y alcance.

Las [medidas por evento del 16 de octubre](reports/engineering/cpu-view-host-work-20261016/README.md) alcanzan entre 18.600 y 19.600 filas/s en Titans-MAC y entre 10.200 y 10.600 en M1, sin lectura de la vista ni pasos de optimizador. Las de [B+M y B+C+M](reports/engineering/codec-projection-panels-20261015/README.md#recorrido-del-lector) quedan entre 8.400 y 8.700 filas/s. Son límites superiores del caudal de una ventana completa. No justifican aplicar a todas las familias las 33.300 filas/s de un Transformer ni multiplicar las mejoras de distintos cambios. La [proyección de horas](docs/research/training-campaign-2000.md#proyección-de-horas) sigue incompleta para la GRU candidata, varias familias de adaptadores, los comparadores tabulares y las políticas.

Las referencias y los cuatro controles de Titans-MAC tienen entrenador por ventana y están declarados en las configuraciones de A y A v2. La [GRU episódica](docs/engineering/candidate-chronological-trainer.md), [MARS-TITAN con ampliaciones](docs/engineering/mars-titan-extensions.md) y el [factorial de CM-v1](docs/experiments/mars_titan_cm_v1/factorial.md) tienen entrenador, entrada por ventana, traslado y sección en la configuración de A v2 y en la declaración ampliada de A. A v2 incluye también K = 4 con episodios de la primera lectura y los ocho modelos B6, incluidos los dos controles kalman de PT3. MARS-TITAN ajusta solo el lector episódico sobre el padre `mac_online` congelado, y con todas las ampliaciones apagadas reproduce bit a bit la sesión de ese padre. Sus quince modelos tienen productor, también [M3](docs/engineering/m3-write-policy.md), que ordena el índice selectivo con error maduro, anomalía y relevancia normalizados con escalas del tramo de entrenamiento de cada ventana y pesos fijos de un tercio. Ocho de ellos no tienen lector: la [corrección B6](docs/engineering/mars-titan-extensions.md#corrección-b6-en-las-ventanas-walk-forward) suma a la predicción del padre una memoria asociativa escrita solo con resultados maduros, con la clave del codec, con una clave constante que la reduce a un corrector de sesgo o con cuatro claves que [reparten la memoria](docs/engineering/mars-titan-extensions.md#enrutamiento-de-b6-por-régimen) por un régimen de mercado observable y, como control, por mes. CM-v1 ajusta dos núcleos `mac_online` auxiliares, uno con C desactivado y otro con C como penalización, y aplica M como retención con centros fijos del banco del lector. La comparación declara además un [análisis por presencia de noticias y fundamentales](docs/research/metrics.md#estratos-por-presencia-de-modalidades), fijado antes de cualquier resultado y solo descriptivo. Ninguno de estos modelos tiene diferencias medidas.

## Alcance y recursos

El [recuento de metadatos de Titans](reports/engineering/state-metadata-sizing-20261018/README.md) evita reconstruir la configuración en cada consulta. En cuatro repeticiones del microajuste reduce la mediana total de 34,38 a 32,22 segundos, con los mismos tensores de modelo y optimizador y las mismas predicciones. No se ha medido todavía su efecto en el universo completo ni se observa ahorro de RAM o VRAM en ese caso.

El equipo de trabajo tiene **32 GB de RAM y una RTX 4070 Max-Q de 8 GB**. La campaña prevista utiliza todo el universo admisible, sin límite de 64 o 128 activos, con un modelo conjunto de Estados Unidos y China y controles separados por mercado para tres familias. La copia original contiene 108,2 GiB. Los datos preparados se guardan en Parquet y se leen por lotes, sin duplicar todas las ventanas en memoria. Los recursos limitan el tamaño del lote y condicionan el tiempo, no justifican presentar un panel pequeño como el corpus completo. El [presupuesto de almacenamiento](reports/resources/storage-budget.md) distingue disco, tensores y memoria. La edición histórica admite modalidades ausentes con máscaras y causas. La estricta exige las cuatro modalidades y los 140 indicadores observados. La falta de precios u objetivos válidos se registra aparte y no se rellena con datos inventados.

La preparación y las representaciones son reanudables. Las referencias neuronales conservan pesos, AdamW, generadores y cursor confirmado, con pruebas de continuidad exacta. La [persistencia comprobada](reports/reproducibility/reference-checkpoints.md) distingue esa implementación de los contratos pendientes de la futura memoria adaptativa. XGBoost recupera la última ronda confirmada. Ridge puede repetir el caso en curso si no terminó. El [plan de cómputo](docs/engineering/compute-plan.md) contempla la disponibilidad del equipo durante las 24 horas, sin confundirla con rendimiento máximo sostenido.

La [revisión de la memoria posterior a Titans](docs/research/post-titans-memory-review.md) deja tres innovaciones para el núcleo de la campaña, cada una desactivable y desactivada por defecto. Su punto de inserción sobre Titans-MAC y las ampliaciones de MARS-TITAN está en el [diagrama del sistema](docs/research/titans-mac-architecture.md#innovaciones-posteriores-a-titans). Ninguna se ha entrenado ni evaluado, así que no hay resultados experimentales.

- **PT1, escritura acotada y contracción condicionada** ([#453](https://github.com/GonxKZ/mars-titan/issues/453)): implementada y comprobada sin entrenar ([documento](docs/engineering/titans-memory-stability.md)). La campaña A v2 la declara con su alternativa trivial como extensiones del núcleo de `titans_mac_online`, con sus mismos casos, semillas y parada. Resultado experimental pendiente.

- **PT2, calibración conformal en línea con etiquetas maduras** ([#454](https://github.com/GonxKZ/mars-titan/issues/454)): implementada, conectada a la comparación por ventanas de A v2 con su alternativa de recalibración periódica y comprobada sin entrenar ([documento](docs/engineering/online-conformal-calibration.md)). La comparación también da su cobertura en cada evento declarado de D2. Resultado experimental pendiente.

- **PT3, regla de Kalman con ruido de cohorte correlacionado en B6** ([#455](https://github.com/GonxKZ/mars-titan/issues/455)): implementada y comprobada sin entrenar ([documento](docs/engineering/kalman-associative-memory.md)). La ventana B6 estima σ² y ϱ con los últimos meses del ajuste y la campaña A v2 la declara con su alternativa ϱ = 0, frente a B6 proximal. Cada predicción lleva su varianza y la de una memoria que recibe las etiquetas una sesión más tarde, y la comparación aplica con ellas los criterios de cobertura y de retraso de la regla. En las vistas reales de US+CN cada cohorte de escritura es exactamente una sesión, así que ϱ se aplica a la misma agrupación con la que se estima. Resultado experimental pendiente.

Una predicción solo puede usar datos disponibles en su instante de decisión. La actualización asociativa de Titans utiliza entradas observadas bajo una política explícita. El error financiero de escritura episódica solo se calcula cuando madura la etiqueta de la predicción realmente emitida. Las tablas contables necesitan fechas de publicación y los gráficos se construyen exclusivamente con ventanas pasadas.

## Empezar

Requisitos: Linux, Git, [uv](https://docs.astral.sh/uv/), GNU Make y ripgrep. La comprobación nativa necesita CMake, Ninja y Clang. El entorno de desarrollo usa Python 3.12, gestionado por uv. La [guía de entorno](docs/engineering/reproducibility.md) recoge las dependencias del sistema.

```bash
git clone https://github.com/GonxKZ/mars-titan.git
cd mars-titan
make setup
make check
```

`make check` ejecuta Ruff, el formato, la comprobación del repositorio y las pruebas rápidas. La [guía de contribución](CONTRIBUTING.md) explica los demás objetivos, como `make test`, `make native-build` y `make test-cuda`, las marcas de las pruebas, el mapa del código y el flujo de ramas y publicación. La suite completa requiere además los binarios nativos, cuya preparación se describe en las guías de [simulación C++20](docs/engineering/native-financial-simulation.md) y [PPO nativo](docs/engineering/native-ppo.md). Las comprobaciones CUDA requieren una GPU libre.

Las comprobaciones se ejecutan localmente antes de publicar cambios. La única excepción autorizada de GitHub Actions es publicar la página de GitHub Pages, sin pruebas ni entrenamientos en GitHub.

Para preparar análisis y entrenamiento en Linux x86-64 con NVIDIA:

```bash
uv sync --locked --extra data --extra research --extra cuda --extra encoders
nvidia-smi
uv run python - <<'PY'
import torch

if not torch.cuda.is_available():
    raise RuntimeError("CUDA no está disponible")
device = torch.device("cuda:0")
print(torch.cuda.get_device_name(device))
print(torch.ones(1, device=device).item())
PY
```

La comprobación falla si no hay CUDA. Los experimentos seleccionarán `cuda:0`. La instalación de PyTorch tiene un índice CUDA explícito y los controles de calidad no requieren descargarlo. Para tareas independientes existe además un entorno compartido compatible: véase [reproducibilidad](docs/engineering/reproducibility.md).

La biblioteca se obtiene desde las fuentes registradas:

```bash
uv run python scripts/fetch_references.py
```

Los fallos de acceso quedan registrados. El catálogo no autoriza redistribuir publicaciones. Los PDF de terceros se conservan en `docs/references/library/`, fuera de Git. Un clon contiene las referencias y el procedimiento de descarga.

Para consultar las fuentes públicas habilitadas y obtener una captura nueva del RSS monetario oficial:

```bash
uv run python scripts/refresh_public_sources.py --list
uv run python scripts/refresh_public_sources.py --source fed_monetary_rss
```

El actualizador necesita `curl`. Sin `--source`, consulta las ocho fuentes renovables validadas. Cada ejecución crea su propio manifiesto y conserva las capturas anteriores. No mezcla actualizaciones con el benchmark ni instala tareas periódicas. Los límites, la selección explícita de documentos PDF y las precauciones temporales se detallan en la [guía de actualización](docs/data/public-source-updates.md).

uv run --locked python scripts/export_observatory.py --output site/data/observatory.json
